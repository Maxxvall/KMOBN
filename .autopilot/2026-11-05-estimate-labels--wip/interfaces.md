# Границы и правила

## Источники

`AGENTS.md`, `carried.md`, `notes.md`, `spec.md`. Пользовательский AGENTS.md не редактируется.

## Правила проекта

- Главные правила проверки — пользовательский AGENTS.md: сервисы и расчёты требуют npm run test; Electron E2E только для desktop integration, build только для packaging/config/release.
- Порядок разделов индивидуален для сметы, сохраняется в её документах; новые разделы добавляются в конец. Короткий клик сворачивает; удержание около 400 мс начинает перенос мышью или пальцем.
- Общая кнопка сворачивания меняет только просмотр.
- Иконки действий нейтральные, удаление красное; «Сохранить» и ИТОГО сохраняют красный акцент.
- Фильтр периода истории не меняет сортировку и экспорт.
- Платежи не возвращаем; остатки прошлого прогона ранее оставляли отдельными.
- Не читать значения .env, credentials и локальные пользовательские данные; не выводить их. Проверки persistence только в изолированной fake-IndexedDB/моках, не в пользовательском workspace.
- Не менять структуру доступа, SQL/RLS/RPC и Electron-интеграцию. Никаких новых зависимостей, global install, push, deploy или обращений к live-данным.

## Границы, решённые в спецификации

### Типы и бизнес-правила меток

- `types.ts`: `EstimateLabelDefinition { id: string; name: string; deleted?: boolean }`; `Estimate.labelIds?: string[]`; `EstimateSectionsDocument.labels?: EstimateLabelDefinition[]`. Необязательность нужна для старых документов и fixtures.
- `services/estimateLabels.ts`: единственный владелец `TYPICAL_PROJECT_LABEL_ID = 'system:typical-projects'`, `MAX_ESTIMATE_LABELS = 2`, нормализации имён/определений/ID, получения активных назначений, AND-сопоставления, системной проверки типового проекта. Экспортируемые имена helpers выбирает исполнитель один раз и фиксирует в возврате; не дублировать правила в компонентах/калькуляторе.
- Встроенная метка всегда ровно одна; protected name/ID, custom IDs стабильные UUID (использовать существующий способ генерации). Не принимать подмену системного определения из внешних данных.
- Эффективное назначение игнорирует удалённые/неизвестные ID и нормализует дубли; оно используется в интерфейсе и ограничении двух меток. Назначение типового проверяется по системному ID, а не тексту.

### Хранение справочника

- Расширить существующие `services/estimateSections.ts`, `services/database.ts`, `contexts/EstimateSectionsContext.tsx` и относящиеся к ним offline merge/conflict пути: пользовательский справочник является частью `EstimateSectionsDocument`.
- Переиспользовать `loadEstimateSections` / `saveEstimateSections`, IndexedDB store `estimate_sections`, существующий RPC `save_estimate_sections` и его CAS/conflict дисциплину.
- Учитывать `labels` в normalize, snapshot, base comparison, merge и конфликтной UI. Tombstone удаления не теряется при нормализации, старом сохранении или конфликте.
- Контекст предоставляет активные определения и async create/rename/delete с существующими loading/error/saving состояниями. На переименование не требуются массовые изменения смет. На удаление — эффективное снятие назначения и защита от stale-ID, без удаления самих смет.

### Назначения и жизненный цикл

- Значения `labelIds` проходят существующий Estimate JSON payload, queued persistence, signature/dirty и lifecycle-функции.
- New version retains; separate clone and calculator draft clear; defaults empty. Не путать дубли версий с отдельным копированием сметы.
- В backup/restore переносится справочник (либо минимальные определения через существующий конверт/snapshot) вместе с ID, включая экспорт только смет. После восстановления названия разрешаются из общего справочника. Share import как новая отдельная смета очищает назначения и не переносит частный справочник; это существующий путь копирования.

### UI

- Переиспользуемый picker/управление метками для истории и редактора, в стиле текущего приложения. Компонент не владеет бизнес-валидацией или сохранением справочника.
- `EstimateMetaFields` добавляет подписанное поле с выбором максимум двух активных ID.
- `EstimateHistory` применяет AND после существующих базовых фильтров только при `archiveView === 'current'`. Пустой выбор — все; отдельный режим без меток. Выбранные удалённые ID очищаются.
- Использовать доступные checkbox/button, видимый focus, Escape/click outside, связанный label, aria-expanded; не имитировать menu-роль для сложной формы. На узком экране dropdown и поле остаются в viewport, touch targets около 44px.
- По Impeccable context уже выполнен: narrow extension, incumbent UI — визуальный источник. Новый PRODUCT.md/DESIGN.md не нужен; не запускать context второй раз. Перед UI-правкой прочитать craft-floor.md; после законченного UI однократно detector по изменённым файлам.

### Источники расчёта

- Все входы калькулятора/AI проходят один фильтр по системному ID, валидным данным и неархивности. Удалить ограничения статуса/свежести для типовых; исключить старые версии актуальной цепочки.
- `selectEligibleHouseHistory`, `selectHouseHistoryForAi`, основной `calculateHouseEstimate` и вызовы AI в `HouseCalculator`/сервисе не обходят фильтр при fallback или refresh.
- Обычные estimates не передаются в ценовой AI summary, дополнительные позиции или резервный расчёт. Нет источников — русское сообщение, без обращения к AI за подменой.

## Проверки и швы

- Чистые helpers: AND-пример «Типовые проекты»+«Баня», лимит/нормализация, rename/delete и старые пустые данные.
- Существующие persistence-тесты с fake-IndexedDB/моками: сохранение/reopen меток и справочника, offline snapshot/merge/conflict, JSON roundtrip без потери данных; без мутаций реальных хранилищ.
- Lifecycle/signature: labels-only change сохраняется; version retains, clone clear, calculator draft clear.
- Калькулятор: unlabelled approved не источник; labelled old draft допустим; только одна из двух меток не проходит AND; AI/fallback не обходят restriction; нет типовых — понятный отказ.
- Новое значимое поведение проверять RED → GREEN; не создавать тесты классов CSS/текста/внутренних вызовов.
- Адресно: `npm run test -- services/estimateLabels.test.ts` или другие затронутые файлы.
- Финальный CI gate: `npm run check` (typecheck frontend+Electron, lint, test). Выполняет один исполнитель после своих изменений, сохранив реальный exit code; координатор переиспользует evidence неизменного кода.
- Не запускать Vite, Electron, Playwright, build или E2E для этой задачи. Локальный браузер отключён в Work; визуальная проверка остаётся явным ограничением, код/дифф проверяет независимый reviewer.
