## Что должно заработать

Импорт не создаёт две метки с одинаковым нормализованным именем под разными ID и не сохраняет половину файла при отказе. Поздний cache-update старого пользователя не подменяет справочник нового пользователя.

## Критерии приёмки

- [ ] Spec · services/estimateLabels.ts:56 · импорт объединяет определения только по ID и создаёт одноимённые активные метки с разными UUID. Воспроизведено: `Bath` + `  BATH  ` сохраняются обе. Согласно spec §1, дубликаты нормализованных имён должны отклоняться понятной ошибкой до любых записей и offline-операций; частичный импорт недопустим.
- [ ] Craft · App.tsx:354 · поздний `estimate_sections` cache-update старого аккаунта после переключения принимается новым аккаунтом и показывает прежний справочник. Новая проверка владельца при сохранении предотвращает постановку чужого документа в очередь, но обработчик события также должен проверять `loaded.id === supabaseUser.id`. Путь подтверждён чтением кода, runtime-воспроизведения нет.
