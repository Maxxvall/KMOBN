# Спецификация: Исправления дельта-аудита и UX больших экранов

## Задача
Пользователь заказал аудит и попросил «исправь все это» — устранить находки отчёта `AUDIT_REPORT_2026-11-13.md`: потерю меток смет в двух сценариях, мелкие дефекты свежего WIP-баннера обновлений, рассинхрон бизнес-правил (кровля, ё/е, санитайзеры), накопленную косметику и неуютный интерфейс на мониторах 1920–2560px, где контент растягивается на всю ширину, а навигация спрятана в мобильный drawer.

## Решение
- Смета с метками перестаёт терять метки: ни при сохранении без загруженного справочника, ни при восстановлении старого бэкапа.
- Баннер обновлений честно показывает состояние: «загрузка идёт» не сбрасывается закрытием баннера; в профиле нет второй активной кнопки скачивания во время загрузки. Незакоммиченный WIP (5 файлов) заезжает одним коммитом.
- Расчёт дома, визард и AI-подсказки считают кровельный материал по одному правилу — по типу крыши (0.95/1.0/1.15/1.25 из калькулятора); когда тип неизвестен — 1.15.
- Русский текст матчится одинаково во всём приложении («Ёлка» = «елка»), имена файлов для PDF чистятся одним санитайзером везде.
- Код без лишнего: мёртвые пропсы редактора, иероглифы, deprecated-обработчики, шумные логи, синхронная запись лога в main-процессе — вычищены.
- На больших экранах интерфейс компактный: единая ширина контента и шапки, липкая шапка и заголовки таблиц, все разделы в строке навигации, формы в один ряд, карточки сетками, окно аналитики растёт с высотой экрана, мастер смет шире.

## Решения по реализации
- **R01/R06/R07 — guard-уровень, без смены модели данных.** Хелпер «какие labelIds переживают сохранение» — чистая функция в `services/estimateLabels.ts` (тестируемая), компонент вызывает её с флагом готовности справочника. R06 — перечитать документ из кэша после успешного сохранения. R07 — условие на id как в обработчике кэша.
- **R02 — различать «поле отсутствует»** через `Array.isArray(e.labelIds)`; сравнение в `hasEstimateChanged` только при наличии поля у входящей записи.
- **R03 — один коммит с явным списком путей** (App.tsx, components/ProfileModal.tsx, components/UpdateBanner.tsx, electron/main.ts, electron/preload.ts, electron/types.ts, services/format.ts — main/preload несут удаление cancel-update). Коммит локальный, без push.
- **R11 — два «коэффициента кровли» разведены по семантике (уточнение по notes.md):** 1.3 в AI-промптах и 1.15 в визарде — ОДНА величина (pitch-фактор площади кровли с единицы пятна) → единая экспортируемая константа `ROOF_AREA_PITCH_FACTOR = 1.15` в `houseCalculator`; её используют smartEstimateBuilder (обе ветки материала кровли), `estimateRoofArea` и все 4 места текста промптов openRouterService; хардкоды удаляются. Карта `roofFactor` по форме крыши (0.9–1.25) в houseCalculator — коррекция реальных количеств из смет-референсов, другая семантика — НЕ меняется, документируется комментарием. Порог аномалии `*1.3` (openRouterService:196) не трогается. Значение 1.15 — как у принятого пользователями визарда; AI даёт на ~13% меньше кровельного материала, чем раньше (поведенческое изменение, зафиксировать в отчёте).
- **R12 — ё→е внутрь `normalizeKey`** (`types.ts`); 8 локальных `.replace(/ё/g,'е')` заменяются вызовом единого хелпера там, где семантика совпадает; отличия локальных вариантов фиксируются, а не теряются.
- **R13/R20 — `services/format.ts` становится модулем форматтеров**: `formatBytes`, `formatDuration`, `sanitizeFileName` (тело — самый строгий из трёх существующих вариантов; отличия сверить перед заменой).
- **R18 — удаляются только `console.log/info/debug`**; `error/warn` остаются (ошибки синка/сервиса нужны в devtools).
- **R22/R31 — tailwind.config**: `maxWidth: { '8xl': '93.75rem' }` (1500px — совпадает с существующими Cutting/HouseCalculator) и `screens: { '3xl': '1920px' }`.
- **R28 — высота виртуализации** через clamp в inline-style (JS), графики — через уже существующий паттерн matchMedia (`useIsDesktopViewport`-стиль), без нового общего хука, если он не понадобится второму тикету.
- **UX-тикеты не перекраивают принятый редизайн смет** (fa9ad3c): редактор — только ширина и плотность; ASSUMPTION принято за пользователя (брифинг без ответа).
- Прежние мелкие баги и lint warnings взяты доводкой 14.11 (R35-R38); мобильный text-xs и кровля −13% — вне рамок (см. ниже).
