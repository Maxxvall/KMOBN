Короткая инструкция по размещению приложения (Vite + React) на Vercel или Render

Коротко — что выбрать
- Рекомендация: **Vercel** — проще и удобнее для статических фронтенд-приложений (Vite). Быстрая авто-детекция, CDN, бесплатный план для большинства личных проектов.
- Render — тоже подходит (есть статические сайты и веб-сервисы). Берите Render, если планируете хостить бэкенд на одном сервисе вместе с фронтендом.

Общие предпосылки
- У вас есть аккаунт GitHub (или GitLab). Проще подключать репозиторий к Vercel/Render.
- Репозиторий можно публичным или приватным (оба сервиса поддерживают приватные репо на бесплатном плане, но GitHub проще). 
- В проекте команда сборки: `npm run build` (в `package.json` это `vite build`). Выходная папка по умолчанию — `dist`.

Шаги — быстро и по факту (Vercel)
1. Сохраните и закоммитьте проект, если ещё не сделали. Примеры команд (PowerShell):

```
git add .
git commit -m "prepare for deploy"
git branch -M main
git remote add origin <URL-репозитория-на-GitHub>
git push -u origin main
```

2. Зарегистрируйтесь на https://vercel.com и подключите GitHub/GitLab.
3. Нажмите «New Project» → выберите репозиторий → импорт.
4. При импорте укажите (если не определится автоматически):
   - Build Command: `npm run build`
   - Output Directory: `dist`
5. Добавьте нужные переменные окружения в разделе Settings → Environment Variables (если у вас есть API-ключи, и т.д.).
6. Нажмите Deploy — сайт сразу будет доступен по бесплатному домену `*.vercel.app`.

Шаги — быстро и по факту (Render)
1. Пуш репозитория на GitHub (см. команды выше).
2. Зарегистрируйтесь на https://render.com и подключите GitHub.
3. Нажмите «New» → «Static Site» (если ваше приложение — статический фронтенд).
4. Выберите репозиторий и укажите:
   - Build Command: `npm run build`
   - Publish Directory: `dist`
5. Установите переменные окружения, если нужно.
6. Нажмите Create и дождитесь деплоя. У Render тоже будет бесплатный домен и HTTPS.

Короткие отличия и советы
- Простота: Vercel обычно быстрее настроить и лучше оптимизирован для фронтенда.
- Если нужен бэкенд рядом с фронтом (например сервер на Node), Render может быть более универсальным (Web Service). Но бесплатный Web Service на Render может засыпать.
- Оба сервиса имеют лимиты по бесплатному трафику/использованию — проверьте в личном кабинете при нагрузке.

Проверка локально перед деплоем
1. Установите зависимости: `npm install`.
2. Соберите: `npm run build`.
3. Убедитесь, что в корне появилась папка `dist` и в ней `index.html`.
