# Разделы сметы

Встроенные разделы описаны единым registry `ESTIMATE_SECTION_DEFINITIONS` в `types.ts`. Для каждого раздела там задаются неизменяемый идентификатор, отображаемая подпись, порядок, допустимые подгруппы, иконка и синонимы для AI-нормализации.

## Правила совместимости

- Значение `EstimateCategory` хранится в JSON payload смет, материалов, работ и комплектов. Существующие значения нельзя переименовывать без миграции данных.
- `ОБЩАЯ` — специальная категория каталога. Её позиции доступны во всех разделах, но саму категорию нельзя добавлять как пустой раздел новой сметы.
- Редактор и генераторы документов обязаны показывать неизвестные значения category из сохранённых данных. Это позволяет новой версии приложения открыть смету с будущим или пользовательским разделом без потери позиций.
- Пустые разделы сохраняются в `Estimate.selectedSections` и синхронизируются тем же payload, что и смета.

## Добавление встроенного раздела

1. Добавить стабильное строковое значение в `EstimateCategory`.
2. Добавить одну запись в `ESTIMATE_SECTION_DEFINITIONS` с уникальным `order` и непересекающимися AI aliases.
3. Если раздел входит в типовой состав объекта, добавить его в соответствующий preset `AIGenerationModal`.
4. Запустить unit tests, web build и Electron offline E2E.

Dropdown-списки, порядок редактора, PDF, сравнение версий и AI используют registry через `services/estimateSections.ts`; отдельные списки разделов в компонентах добавлять не нужно.

## Будущий пользовательский редактор

Для пользовательского добавления, переименования, скрытия и сортировки разделов registry нужно хранить в отдельной синхронизируемой таблице `estimate_sections`. Идентификатор раздела остаётся неизменяемым, а название и порядок редактируются отдельно. Используемый раздел архивируется вместо удаления; удаление разрешается только при отсутствии связанных смет, материалов, работ и комплектов.

Новая таблица должна войти в Supabase RLS, IndexedDB cache, offline queue, backup/export и импорт одной сметы. В обменный файл пользовательской сметы нужно включать определения нестандартных разделов, сохраняя поддержку текущего формата импорта.
